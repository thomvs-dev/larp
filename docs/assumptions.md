# Modelling assumptions

Every assumption about circuits, published macros or simulator semantics goes here, with a source.

## Part A — bit_accurate mode

| # | Assumption | Source / reason |
|---|---|---|
| 1 | Two's complement for weights and activations; weight MSB plane and activation sign cycle carry negative weight | ASiM `module/asim_linear.py` (`_decompose_weight`, `_decompose_feature`) |
| 2 | Each weight bit is a separate physical column; one ADC conversion per (column, input cycle, row chunk) | ASiM loop structure |
| 3 | ADC full scale = `nrow × L_c` even for a shorter last chunk; uniform `2^b - 1` steps over full scale | ASiM (`mac / nrow`, `round(mac * (2^adc - 1))`) |
| 4 | Random noise: Gaussian, σ in % of full scale, per conversion | ASiM `rand_noise_sigma` |
| 5 | Nonlinearity: Gaussian, σ% / sqrt(v·nrow + 1), per conversion (v = normalised MAC) | ASiM `non_linear_sigma` (form copied as-is; physical meaning to be checked in A7) |
| 6 | Hybrid: cycles with i + j > B_w + n_cycles − hybrid_levels − 2 get no noise but are still ADC-quantized | ASiM |
| 7 | Bit-parallel signed inputs: sign bit in its own cycle; magnitude bits grouped from LSB, top group may be smaller | ASiM |
| 8 | Quantization scale = absolute max (per tensor in ASiM; per channel / per token also offered) | ASiM + standard LLM practice |
| 9 | LM head kept digital (not swapped) by default | Common practice; vocab projection is large and accuracy-critical |
| 10 | Calibrated ADC range (`adc_range: calibrated`): ADC full scale set per layer / cycle / (cycle, plane), integer MAC units, values above it saturate at the top code | Option beyond ASiM; models a programmable ADC reference. Calibrated on ideal (fake-quant) activations from separate calibration data (LLM: WikiText-2 train split) |
| 11 | Analog noise stays relative to the nominal full scale nrow·L_c when the ADC range is calibrated | Noise comes from the array (bit-line charge), not from the ADC reference |
| 12 | Asymmetric weights (`w_quant: asymmetric`): unsigned weight planes, zero-point term z·Σx subtracted digitally and exactly | Option beyond ASiM; Σx per row assumed available digitally (input buffer) |
| 13 | Conv layers: unfolded rows grouped by whole input channels, floor(nrow / (kh·kw)) channels per array activation; all groups computed | ASiM `asim_conv.py` grouping, without its group-skipping issue (findings F4) |
| 14 | Conv activation scale: `per_tensor` = whole input batch (ASiM), `per_token` = per image | ASiM uses the batch max |

## Part B — cost model (B0)

Every per-action cost parameter used by `cimsim/circuits/` is listed here with its source. Values marked
"reference line" are survey envelopes, used until GATE B1 calibrates each macro.

| # | Assumption | Source / reason |
|---|---|---|
| B-1 | ADC energy per conversion (`arch: bound`) = max(Walden, Schreier) with FOM_W · 2^ENOB and ½ · 10^((SNDR − FOM_S)/10), SNDR = 6.02 ENOB + 1.76 | Walden, IEEE JSAC 1999 (FOM_W); Schreier & Temes 2005 (FOM_S); use of the two as energy bounds: Murmann, "Energy Limits in A/D Converters" (talk, 2012), also the basis of the CiMLoop ADC plug-in (Andrulis et al., arXiv 2404.06553) |
| B-2 | Reference values FOM_W = 10 fJ/conv-step, FOM_S = 170 dB (`config/circuits/adc_survey_lines.yaml`) | Reference lines drawn on the ISSCC/VLSI 1997–2012 survey plot in Murmann 2012 (above). Not best-in-class: the best SAR FOM_W reported by 2022 is ~0.4 fJ/conv-step (Tang et al., IEEE TCAS-I 69(6), 2022) |
| B-3 | Throughput per ADC not modelled; bound model valid below the survey's speed corner (~100–300 MHz) | Murmann 2012. CiMLoop's plug-in adds throughput-dependent bounds; to add when the mapper (B2) fixes ADC rates |
| B-4 | Flash ADC energy = (2^b − 1) comparator decisions + fixed term; `e_comparator` has no default and must be cited per macro | Comparator count of a flash ADC; M2 (Sinangil JSSC 2021) uses a 4-b flash |
| B-5 | ADC energy is charged on `adc_conversions` (all input cycles), not `adc_conversions_analog` | Hybrid (digital) cycles are still ADC-quantized (#6) |
| B-6 | 1 MAC = 2 ops in all TOPS/W and TOPS figures | Common convention; confirmed for M2 by 1024 MAC × 2 / 5.5 ns = 372.4 GOPS (`validation/macro_calibration.md`) |
| B-7 | DCIM energy per 1b × 1b product = e0 + e1 · input toggle rate; weight-ones fraction fixed at the calibration value (50 %) | Structure: Chih ISSCC 2021 (energy depends on toggle rate and weight sparsity, mostly first adder-tree stages). e0, e1 fitted to its 89 / 52 TOPS/W at 18 / 50 % toggle (`results/b1_m4_chih/`) |
| B-8 | DCIM pass time = (x_bits + 1) · t_cycle; a w_bits weight occupies ⌈w_bits / 4⌉ 4-b columns | Chih ISSCC 2021 text (extra accumulator cycle) and Fig. 16.4.6 (10 ns at 4b, 18 ns at 8b; 3300 / 917 GOPS) |
| B-9 | Input toggle rate = fraction of bit transitions per input line, inputs streamed bit-serially MSB first, token after token | Chih ISSCC 2021 (MSB-first bit-serial input); measured on per-token 8-b activations by `scripts/b1_toggle_rates.py` |
| B-10 | No supply-voltage or node scaling: each fitted spec is valid only at its calibration VDD and node | Holds inside `ADCSpec` and `DCIMSpec`: they never rescale themselves. Moving a number to another node / VDD is an explicit call to `ScalingRule` (B-11) |
| B-11 | Node / VDD scaling: energy ∝ node^a · VDD², area ∝ node^2, delay ∝ node^1, a = 1 (`config/circuits/scaling.yaml`). Used only to move a cited or calibrated cost to the result node | Constant-field scaling (C ∝ dimension, E = C V²): Dennard et al., IEEE JSSC 9(5):256, 1974. Known limit: below ~22 nm node names are not dimensions and energy scales more slowly; Stillmaker & Baas (Integration 58, 2017) and Sarangi & Baas (DeepScaleTool, arXiv 2102.10195) fit this from simulation / foundry data and differ from each other by ~25 % in power for 10 → 7 nm. The exponent is a config field; B1 reports how far the rule is off between the calibrated macros at 65, 22 and 7 nm |
| B-12 | Integer adder 3.125 fJ per bit, integer multiplier 3.027 fJ per bit² at 45 nm, 0.9 V (`config/circuits/digital_45nm.yaml`) | Horowitz, "Computing's energy problem (and what we can do about it)", ISSCC 2014, paper 1.1, Fig. 1.1.9: 32-b add 0.1 pJ, 32-b multiply 3.1 pJ. The per-bit values give the published 16-b add (0.05 pJ) exactly, 8-b add 0.025 pJ (published 0.03, −17 %), 8-b multiply 0.194 pJ (published 0.2, −3 %); `tests/test_circuits_digital.py` |
| B-13 | On-chip SRAM buffer read 156 fJ per bit at 45 nm; table (LUT) reads of the non-linear units cost the same per bit | Horowitz ISSCC 2014, Fig. 1.1.9: 32-b read from an 8 KB SRAM 5 pJ. Larger buffers cost more per bit (same figure: 32 KB and 1 MB caches 2× and 10× the 8 KB value); buffer-size dependence is a B3 item |
| B-14 | Register (flip-flop bank / small register file) access 7.5 fJ per bit at 45 nm | Pedram, Richardson, Galal, Kvatinsky, Horowitz, "Dark Memory and Accelerator-Rich System Optimization in the Dark Silicon Era", IEEE Design & Test 2017 (arXiv 1602.04183), Table I: 16-word register file, 16 bit, 0.12 pJ. The same table gives a 16-b add at 0.18 pJ against 0.05 pJ in Horowitz 2014 (different design points), so digital per-op energies carry a factor ~3.6 uncertainty; Part B reports the digital share of every total |
| B-15 | Non-linear units as fixed-point operation counts per element (`cimsim.circuits.digital.UNIT_OPS`), 16-bit words: softmax 2 mul + 2 add + 1 table read; RMSNorm 3 mul + 1 add; LayerNorm 3 mul + 4 add; SiLU / GELU 2 mul + 1 add + 1 table read; SwiGLU gate product 1 mul; RoPE 2 mul + 1 add; residual 1 add; plus 2 mul + 1 add + 1 table read per vector for the reciprocal / inverse square root | **Assumption, no silicon source.** Counts follow a table-plus-linear-interpolation implementation of exp / sigmoid / 1/x / 1/√x. To be replaced if a cited transformer accelerator breakdown is adopted |
| B-16 | SAR ADC energy = k · 2^b · C_u · Vref² (capacitor DAC) + b · (comparator decision + logic per bit cycle); k = 1.331 conventional switching, 0.2495 monotonic (`config/circuits/sar_switching.yaml`) | Average DAC switching energy of a 10-bit SAR: 1363.3 C Vref² conventional, 255.5 monotonic (Sanyal & Sun, Electronics Letters 49(4), 2013, Table 1; monotonic: Liu et al., IEEE JSSC 45(4):731, 2010), divided by 2^10. The exact conventional sum at 8 b gives k = 1.325. `c_unit`, `vref`, comparator and logic energies have no default and are cited per macro (M1: 1.2 fF unit capacitor, Jia JSSC 2020 Sec. III-C) |
| B-17 | Analog conversion energy = nrow · (e_wl_cell · pulses per row + e_bl_cell · bit-line activity) + fixed column term + ADC + shift-add (accumulator bits × adder bit) + output register; input register per array cycle (`cimsim/circuits/analog.py`). `e_wl_cell`, `e_bl_cell` have no default: fitted per macro in B1 | Data dependence: Sinangil JSSC 2021 Sec. IV / Fig. 13a (macro energy rises with the MAC result: more RWL pulses and deeper RBL discharge; RWL switching ≈ 5 % of macro power, Sec. III-A); Jia JSSC 2020 Sec. III-B (input broadcast on x / xb and charging of the cell capacitors ≈ 66 % of array energy, proportional to input sparsity). Shift-add and registers use B-12, B-14 |
| B-18 | ADC sharing: `adc_share` columns per ADC; array cycle time = t_array + adc_share · t_adc; ADC count = ⌈columns / adc_share⌉; conversion count and energy unchanged | One conversion per column is still needed; sharing serialises them. Mux energy neglected. Jia JSSC 2020 uses one ADC per column (folded layout); Sinangil one flash ADC per 4-b weight column group |
| B-20 | M2 mapping: one conversion = one 4-b output (4 bit columns × 64 rows = 256 cells, 64 MACs); MAC code m ↔ m RWL pulses per row and bit-line activity m / 15; macro energy linear in the code; data-independent part charged to the 15 flash comparators; wordline part = 5 % of energy at the average point | Sinangil JSSC 2021 Fig. 13(a) (labelled 5.9 pJ average, 7.8 pJ maximum), Sec. III-A (RWL ≈ 5 % of macro power), Sec. III-C (4-b flash, 15 comparators). Which inputs / weights give each code is not stated: "pulses per row = code" is an assumption. The lumped comparator value (19.3 fJ) includes reference and column circuits and is an upper bound for a comparator |
| B-21 | M1 mapping: one conversion = one 2304-cell column for one input bit; array energy 66 % proportional to input activity, 34 % fixed; Table I measured at input activity 0.5; SAR DAC with conventional switching, comparator + logic per bit cycle = remainder of the measured ADC energy; ABN, NMC and reshaping buffer outside the macro figure | Jia JSSC 2020 Table I, Fig. 12, Sec. III-B (66 %), Sec. III-C (8-b SAR, 1.2 fF unit). Activity 0.5 and the switching scheme are assumptions (not stated); the 1b-TOPS/W of the abstract is reproduced by array + ADC with 2 ops per 1-b MAC |
| B-22 | Array write (weight loading) energy anchor: 600 fJ per bit at 65 nm / 1.2 V, 300 fJ at 0.85 V, = 55.2 × one 1-b MAC of the same macro | Jia JSSC 2020 Table I (CIMA load 19.2 / 9.6 pJ per 32-b word), Fig. 12. Includes the loading data path of that chip, not only the bit-cell write; to be used in B3 |
| B-23 | DRAM read energy 3.97 pJ per bit by default (`config/system/dram.yaml`), with 14 pJ (GDDR5) and 20 pJ (DDR3-era) as alternatives | O'Connor et al., "Fine-Grained DRAM", MICRO 2017: HBM2 ≈ 3.97 pJ/bit, the most efficient DRAM in that comparison; GDDR5 14.0 pJ/bit (Fig. 1a). Horowitz ISSCC 2014: 640 pJ per 32-b DRAM read. No LPDDR5 energy per bit was found; the default is therefore a lower bound for an edge system, so the weight-streaming share is a lower bound |
| B-24 | DRAM bandwidth 12.8 GB/s per channel, one channel | Micron LPDDR5 data sheet (MT62F): 12.8 GB/s maximum bandwidth per x16 channel at 6400 Mb/s per pin; JEDEC JESD209-5 |
| B-25 | Result-system analog arrays = the calibrated M1 macro (Jia JSSC 2020) moved to 22 nm / 0.8 V by B-11, with the run's nrow and ADC bits; SAR DAC ∝ 2^bits, comparator + logic ∝ bits; shift-add and registers from the digital library (B-12, B-14); input bit density 0.47 | M1 is the calibrated macro with the simulator's computation model (bit-serial inputs, bit-sliced weights, one ADC per column and input cycle). Density: `results/a5o_qwen15b/summary.md` (sign-plane density 0.39–0.47 per role). M1 was measured at 2304 rows per conversion; using it at nrow 128 keeps its per-cell and per-ADC energies and assumes they do not depend on column length |
| B-26 | Array write energy 90 fJ per bit at 22 nm / 0.8 V for weights, keys and values | B-22 (600 fJ at 65 nm / 1.2 V) × B-11 factor 0.150. Includes the loading data path of the M1 chip |
| B-27 | Residency policy: weights that fit in the on-chip array budget stay; otherwise the largest layer's arrays are working space, the rest of the budget holds resident layers in model order, and every other layer is read from DRAM and written into the working arrays once per token in decode and once per prompt pass in prefill | Design assumption of the analytic mapper (`cimsim/mapper`), no search. Prefill processes all prompt tokens through a layer before the next layer is loaded, which needs a buffer of one activation matrix (not costed) |
| B-28 | LM head (d_model × vocabulary) is a digital INT8 MAC unit whose weights are read from DRAM for every decoded token and once per prompt in prefill | Part A keeps the LM head digital (#9). Its 1.87 Gbit (Qwen2.5) are not in the CIM arrays, so each use streams them; an on-chip copy or a reduced-vocabulary head would remove this term and is not modelled |
| B-29 | KV cache "buffer": 8-bit keys / values in an on-chip SRAM buffer (B-13), read once per attended position, attention matmuls on the digital MAC unit; "array": keys / values written into CIM arrays (B-26), attention matmuls analog with the event counts of `cimsim.core.attention`. Latency bound = DRAM stream time + one array evaluation (10 ns at 65 nm, scaled) per input cycle and layer | Buffer read energy is the 8 KB SRAM value of B-13, optimistic for a multi-megabit buffer. Evaluation time: one 100 MHz clock of the M1 chip (Jia Table I); the paper does not state cycles per evaluation |
| B-30 | DCIM compute macro in the result system: M4 calibration (energy per 1b × 1b product = 0.842 fJ + 3.123 fJ × toggle rate at 22 nm / 0.72 V) moved to 0.8 V by VDD², 8 b × 8 b, input toggle rate 0.31; weights live in the DCIM arrays and are written at B-26 cost | `results/b1_m4_chih/`; toggle rate from `results/b1_toggle_opt125m_sandbox/` (OPT-125M q/k/v, out_proj, fc1: 0.31–0.32). Not measured on Qwen; 8 b × 8 b is outside the fitted 4 b × 4 b points (held-out check −9.9 %) |
| B-31 | Digital baseline: INT8 MAC unit (B-12) with each weight read from an on-chip SRAM buffer (8 bits × B-13) per MAC; streamed weights are written into that buffer at the B-13 energy per bit | Design assumption. The buffer read is the 8 KB SRAM value, optimistic for a buffer of 100 Mbit and more |
| B-32 | ADC anchor variants for the analog arrays: `m1` = SAR of the calibrated M1 macro at 22 nm (B-25); `best_sar` = Walden figure of merit 0.4 fJ per conversion step (B-2 survey line) | `best_sar` is a survey bound, not a calibrated macro, and ignores what a column-pitch ADC next to an array can reach; it brackets the ADC share from below |
| B-19 | Result node 22 nm at VDD 0.8 V (`config/circuits/scaling.yaml` `target`) | Node: `docs/decisions.md`, 2026-11-11. VDD: provisional choice (`docs/decisions.md`, 2026-11-15), near M4's measured 0.72 V; to be fixed when B1 anchors the 22 nm numbers |
