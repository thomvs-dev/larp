# Design decisions

Each entry: date — decision — reason. Finding numbers (F…) refer to `docs/findings.md`.

- 2026-11-02 — Focus on edge SLMs (≤ ~1.5B) — bit-accurate sim of 7B+ not feasible on student hardware; on-chip SRAM story fits edge.
- 2026-11-02 — Build own core (not a fork), use ASiM as reference — need clean support for event counting, DCIM/hybrid, dynamic matmuls; ASiM reproduction is the correctness check.
- 2026-11-02 — Part A before Part B — SRAM analog accuracy on LLMs is the clearer gap; event counters in A make B mostly bookkeeping.
- 2026-11-02 — ASiM is Apache 2.0: reuse of ideas and code allowed with attribution; kept out of repo (git-ignored `third_party/`).
- 2026-11-02 — bit_accurate mode copies ASiM semantics exactly (incl. full scale = nrow on short chunks, nonlinearity form) — so GATE A2 is like-for-like. Deviations become separate config options, never silent changes.
- 2026-11-02 — Default quantization for LLMs: per-channel weights, per-token activations; ASiM's per-tensor kept as an option — per-tensor is known to hurt LLMs badly (E0 will show by how much).
- 2026-11-02 — LM head excluded from swapping by default (kept digital).
- 2026-11-02 — ADC range calibration defaults to MSE (squared readout error on calibration data, ties → largest full scale) — percentile clipping hurts at ≥7 b because clipped conversions land on planes with shift-add weight up to 2^14 (F5). Calibration statistics are taken with all CIM layers in ideal mode, on data separate from evaluation (LLM: WikiText-2 train).
- 2026-11-02 — A2 uses a pretrained CIFAR-10 ResNet-20 (chenyaofo) instead of ASiM's ResNet-18 example — ASiM ships no trained weights and QAT-training ResNet-18 on a CPU is impractical; the comparison only needs both simulators on the same weights. Stem conv and classifier stay in float in both.
- 2026-11-02 — GATE A2 criterion refined (approved by the author): ≤1% at ADC ≥ 8 b and fake-quant; at ADC ≤ 6 b within run-to-run spread — whole-network results are chaotic there even with identical per-layer semantics (F6).
- 2026-11-02 — Pipelined ADC considered (the author's question): not the default for the macro — at the 6 b that F5 shows is sufficient, SAR/flash are cheaper; pipelined needs residue amplifiers (area, static power), heavy column sharing (serialised conversions), adds latency, and its error pattern (large errors at stage-transition codes) is the worst case under 2^14 shift-add amplification. Kept as a simulated option: error model in A7, cost and sharing in B0/B3, so the comparison is made with numbers.
- 2026-11-02 — Results (`results/*/`) are tracked in git (small JSON/YAML) so every number in the log is reproducible from the repo. Large artefacts, if any later, go elsewhere.
- 2026-11-02 — Evaluation window = model context length, capped at 2048 (OPT/Qwen/TinyLlama 2048, GPT-2 1024) — matches quantization literature so baselines compare directly with published tables (OPT-125M reproduces 27.65). CPU bit-accurate subset defined by tokens (first 8,192) rather than windows.
- 2026-11-02 — No GPU: project is CPU-only. One codebase, two executors (`fast` default, `reference` kept for ASiM-exact checks) rather than a separate CPU codebase — a fork would drift from the validated semantics. Whole-model bit-accurate runs limited to OPT-125M/GPT-2 on the first 8,192 tokens; full-set and result-model numbers come from statistical mode (A3).
- 2026-11-03 — Statistical mode uses the analytic model M3 (no fitting to bit-accurate runs) instead of the planned fitted M1 — measurements show the error is a deterministic gain plus input-independent Gaussian noise, both computable from the MAC histogram (≤ 0.2 % on 180 layer-configs); it also extrapolates to unmeasured configs, which A5 needs. Known limit: nonlinear rounding error at full-range ADC 6 b (F3 regime) overestimated 2.3×.
- 2026-11-03 — GATE A3 configs revised: noise 0.25 / 0.5 / 1 % replaced by 0.08 %, 0.10 % and 0.2 % with hybrid_levels 6, with calibrated ADC 6 b on every layer incl. fc2 — the old levels make every layer's error larger than its signal (F7), and an 8-bit fc2 passes noise that 6-bit layers round away.
- 2026-11-03 — GATE A3 noise configs evaluated on 4,096 tokens with bit-accurate seed spread (seeds 0, 1); noise-free configs on 8,192 tokens with fast-vs-reference spread — noisy bit-accurate runs cost ~0.42 s/token on the i7-12700H (noise sampling dominates).
- 2026-11-03 — Statistical mode computes ADC saturation exactly (sparse) instead of modelling it — saturation is deterministic, sparse and correlated across planes (F8); no Gaussian approximation matched it. Option chosen by the author over a covariance-corrected Gaussian (wrong error shape) and per-layer bit-accurate fallback (≤ 4× speed-up).
- 2026-11-03 — Saturation candidates limited by calibration column maxima (`stat_sat_margin`, default 8 MAC units) — the strict popcount bound flags ~half of all conversions at plane density ≈ 0.5 and costs ~15 % of a bit-accurate pass. Assumption: a column that never came within 8 MAC units of saturating on 2,048 calibration tokens does not saturate at test time. `stat_sat_margin: null` restores the strict bound for checks.
- 2026-11-03 — F9 fix: the author chose A1 (exact sparse deterministic term) + B1 (discrete code-flip sampling) over accepting the limits. Flip sampling uses exact thinning instead of a flip rate averaged over MAC values, so the per-conversion distribution equals the bit-accurate executor's. Discrete sampling only for per-conversion flip probability ≤ 0.05 (Poisson placement is wrong when flips are frequent) and < 4 expected flips per output.
- 2026-11-03 — Approved by the author 2026-11-04 (with the distribution rule below): for noisy GATE A3 configs, compare the median statistical PPL with the median of ≥ 5 bit-accurate seeds (`--ref median`); at the noise cliff a single bit-accurate seed is not a stable reference.
- 2026-11-03 — Result model for the A4/B4 headline results: Qwen2.5-1.5B (the author). Fits the 16 GB machine in statistical mode; 3B would need int8 weight storage and ~day-long runs. (There is no Qwen2.5-2.5B.)
- 2026-11-03 — Part B started in parallel with A3/A4 (the author) — B0/B1 are literature + modelling work in the cloud VM and do not compete with the bit-accurate runs on the local machine. Energy numbers for Qwen come from statistical-mode event counts, so they still depend on GATE A3 for accuracy; no TOPS/W figure is reported before GATE B1.
- 2026-11-03 — Calibration macros: CiMLoop's validated SRAM set (Jia JSSC 2020, Sinangil JSSC 2021, Wang JSSC 2023) plus one digital CIM (Chih ISSCC 2021) — open CiMLoop models allow a direct B5 comparison, and the set covers bit-serial charge-domain, multi-bit analog and DCIM.
- 2026-11-04 — Approved by the author (2026-11-04), replaces the tolerance = spread rule for noise-cliff configs: a config is chaotic if sd of log PPL over ≥ 5 bit-accurate seeds > 0.10; then pass needs Mann-Whitney p > 0.05 (≥ 5 vs ≥ 8 seeds), statistical median inside the bit-accurate interquartile range ± 2 %, and layer-level agreement (std ratio within 10 %, non-zero fraction within 5 %). Other configs keep 2 %. Reason: rn010 tolerance = spread = 131 % accepts almost any result.
- 2026-11-04 — Discrete flip sampling only where it changes the error shape: a layer keeps discrete flips if they give its output error an excess kurtosis ≥ 1, otherwise Gaussian — with many flips per output the two give the same result (rn02_hyb6: v2 Gaussian 29.444 = v3.1) and the discrete path costs an exact MAC per flip (450 ms/token vs 12.5).
- 2026-11-04 — Mapping policy as a per-layer `macro` field (acim / dcim / digital) rather than separate layer classes — one layer type keeps quantization identical across macros, so a perplexity difference between policies comes only from analog error; dcim and digital are exact integer compute and differ only in the events Part B costs.
- 2026-11-04 — Quantized weight codes cached as int8 / uint8 (w_bits ≤ 8) and converted to float per call — the float32 cache doubled linear-weight memory, which does not fit Qwen2.5-1.5B on the 16 GB machine. Outputs unchanged (all tests pass).
- 2026-11-04 — Attention matmuls via the HF attention-function registry (custom implementation `cim`) instead of patching model classes — one function covers OPT, GPT-2, Llama and Qwen2 and leaves model code untouched; fp mode reproduces eager attention to 1e-5.
- 2026-11-04 — Keys quantized per channel (scale folded into Q), values per position (scale folded into P) by default — per-token keys cost +4.2 % PPL on Qwen2.5-0.5B, per-channel 0 % (F10); both folds keep both array operands integer.
- 2026-11-05 — Zero-shot runs use lm-eval-harness with the model object passed in (not a model name), 0-shot, the first N documents of each task (`--limit`, lm-eval does not shuffle) so that every config sees the same questions, and paired statistics (McNemar, paired interval) instead of comparing two independent accuracies — differences between configs are ~1 pp, smaller than the unpaired standard error at N = 1,000 (~1.5 pp). N = 1,000 per task as a start: full HellaSwag (10,042 docs, ~3.8M tokens) would take days in statistical mode on the local machine.
- 2026-11-05 — Zero-shot batch size: 1 when attention runs on CIM (right padding would enter the per-channel key scales, F10), 8 otherwise — with linear layers only the padded positions cannot affect the real tokens, and batching removes most of the per-call overhead of statistical mode on short requests (noise-free scores identical to batch 1, `tests/test_zeroshot.py`).
- 2026-11-06 — Statistical-mode short-call speed moved from A5 into A4 as a sub-task — measured 51–73 ms/token on 0.5B zero-shot makes the TinyLlama and 1.5B zero-shot runs 12–24 h each; vectorising the (chunk, cycle) loop is needed before they run. Milestone order unchanged; the A5 item stays with a note. (the author to confirm.)
- 2026-11-08 — Zero-shot requests carry no BOS token (`add_bos_token=False`), for every model — lm-eval 0.4.0–0.4.8, which most published zero-shot tables used, encode causal-LM requests without special tokens; 0.4.13 keeps the tokenizer default, and with `<s>` TinyLlama v1.1 drops 13 pp ARC-e in FP32 (F11). Qwen2.5 has no BOS token and gets identical inputs, so its zero-shot runs stand.
- 2026-11-09 — Calibration histogram cache on by default, per layer, in git-ignored `calib_cache/` — histograms depend only on the model, the calibration data and quantization / nrow / encoding settings, and recomputing them is 98 % of calibration time; per-layer entries let a sweep that changes one role's nrow recompute only that role. Key errs on the side of a miss: any config field not on the known-independent list is part of the key.
- 2026-11-11 — ADC full-scale candidates include (2^b − 1)/n as well as integers (the author chose option A) — with integers only, any ADC with 2^b − 1 > nrow · L had no exact full scale and was simulated worse than a smaller ADC (F12); a real ADC reference is not restricted to integer MAC values. Sweep base changed to all layers ADC 8 b (lossless with full scale 127.5) so one layer type is measured without base error; GPT-2 collapses with the old 6 b base.
- 2026-11-11 — Part B process node 22 nm  — M4 (Chih) and M3 (Wang) are 22 nm, so result numbers need no node scaling from those anchors; M1 (65 nm) and M2 (7 nm) bracket it for checking a scaling rule. 28 nm has no calibrated macro here.
- 2026-11-11 — Result system: all-analog CIM as the baseline, hybrid (per-role `macro: dcim`) as a B4 sweep axis — Part A shows all-analog at calibrated ADC 6 b equals W8A8 on all three result models, so hybrid is an energy / accuracy trade-off, not an accuracy fix. DCIM energy for post-ReLU layers (toggle ≈ 0.025) is outside M4's calibrated range and is reported as such.
- 2026-11-11 — Headline metric: system-level energy / token (macro + digital units + DRAM), prefill and decode separately; macro TOPS/W only as the GATE B1 calibration target — a 1.5B model does not fit on chip, so decode is likely dominated by weight streaming, which macro TOPS/W hides.
- 2026-11-11 — Reduced Part B scope for a tight deadline (the author): GATE B1 on M4 + M2 (+ M3 only if the right PDF arrives; M1 optional); B2 mapper = analytic tile / macro count with a fixed on-chip SRAM budget, no mapping search; B3 DRAM = one cited pJ/bit constant + bandwidth limit; B5 limited to one CiMLoop case or dropped to a discussion paragraph (to confirm). Tasks are simplified, not removed.
- 2026-11-11 — Part A trimmed for a tight deadline ; Part A is the main paper, Part B a shorter section. Kept: ADC bits × nrow per role (steps 1–3), activation outlier statistics, per-role noise sensitivity (reduced), ADC alignment and full-range vs calibrated range as analyses of existing / step-1 data, hybrid (role / layer level), Hadamard rotation, equal-conversion Pareto plot. Deferred: bit-serial vs bit-parallel, input encoding study, statistical speed ≥ 30×, SmoothQuant, noise-aware fine-tuning, all of A7. Reason: the kept items need no new executor features except Hadamard (weight transform), and run on statistical mode or existing data; the deferred ones need new executor options, training, or circuit models.
- 2026-11-13 — Statistical mode is used only at configs where every statistical layer's calibrated ADC step is 1/n MAC unit (the author chose this over restricting calibration to such full scales, or fixing the rounding model) — step 2 shows it is exact there and overestimates the error 7.5× to 3,000× in PPL where calibration picks a fractional step above 1 (F13). The headline results (lossless at 6 b / nrow 128, boundary 2^b − 1 ≥ nrow / 2) are all step-1 points. Cost: no result-model numbers in the partial-clipping regime (o-proj, GPT-2 `c_proj` near the boundary); those stay bit-accurate on OPT-125M / GPT-2. Restricting calibration would change the "calibrated ADC" definition used in F5 / A4; an exact fractional-step model is at least a day and loses most of the speed-up. The check lives in `scripts/run_ppl.py`, not `cimsim/core/layers.py`, so the calibration cache stays valid.
- 2026-11-14 — A5 step 3 reduced to two all-layer points on Qwen2.5-1.5B (nrow 128 / 6 b and nrow 64 / 5 b); nrow 256 / 7 b, below-boundary and per-role points on the result model are not run (the author chose the one-extra-point option after asking to skip the crashing runs) — points at or below the boundary put most conversions on the exact saturation path (13–22 min per 2,048-token window on the local machine), two runs died with an unexplained access violation, and each new nrow costs a 60–90 min calibration; the deadline does not allow it. The per-role boundary map stays a bit-accurate result on OPT-125M / GPT-2; the paper states that the result models were checked at two boundary points only.
- 2026-11-14 — Noise per layer type reported as a threshold result only, no per-type table (the author chose this over a 5-seed bit-accurate per-type table on OPT-125M, ~6 h, and over the statistical table with a caveat) — with a calibrated 1-MAC ADC step, noise below half a step (sigma ≤ 0.05 % of nominal full scale) is absorbed exactly on every layer type (OPT-125M: 25.594 = noise-free on all types and seeds); at 0.10 % the PPL is chaotic in both modes (OPT fc1 layer 1 alone: bit-accurate 52–245 over independent streams) and statistical may be ~2× pessimistic there (p ≈ 0.06), so a per-type ranking would rest on unvalidated numbers. Frees Sunday's local machine time for hybrid / Hadamard / Pareto.
- 2026-11-15 — Part B follows the author's five-step working plan: M1 moves from optional into B1 after M2 (M4 + M2 + M1 can meet the ≥ 3 macro exit criterion without M3, whose PDF is still missing); KV cache in CIM arrays and in an SRAM buffer are both modelled; B4 uses Qwen2.5-0.5B and 1.5B; one local machine decode-trace run checks the derived decode counts — Part A is closed, every Part A run already has `events.json`, so Part B needs no new model simulation and the local machine is free. §4 tasks the plan does not name stay unticked until the author decides.
- 2026-11-15 — Node scaling by the classical rule E ∝ node · VDD², area ∝ node² with the exponent as a config field, instead of the Stillmaker–Baas polynomial fits — the fitted tables are not reproducible from what the cloud VM can read, they disagree with foundry data by ~25 % at 10 → 7 nm (DeepScaleTool), and the rule is only used to move cited digital costs (45 nm) and the M1 / M2 anchors to 22 nm; B1 measures its error across 65 / 22 / 7 nm. Result VDD 0.8 V is provisional (the author to confirm; M4 was measured at 0.72 V).
- 2026-11-15 — Analog array cost is charged per conversion as nrow × (wordline + bit-line energy per cell) with two data terms (pulses per row, bit-line activity), not per array with a fixed tile width — the event counter gives conversions and array cycles, not tile shapes, and both analog calibration macros report energy that is proportional to input activity (Jia) or to the MAC result (Sinangil); the two per-cell energies are the 1–2 fitted parameters per macro.
- 2026-11-15 — Non-linear digital units are costed by operation counts per element that are an assumption (no silicon source, `docs/assumptions.md` B-15) — no cited per-element energy for softmax / norm / activation units at this precision was found; the digital share is reported with every total so the assumption is visible.
- 2026-11-15 — M2 is fitted to the two labelled points of Fig. 13(a) (average and maximum energy), not to the endpoints (codes 0 and 15) — the measured curve steps up between codes 0 and 1 and is linear above; fitting the operating range gives ≤ 6.5 % on codes 1–12 and puts the whole misfit on code 0 (+40 % energy), a point an LLM layer with dense inputs never sits at. The endpoint fit would be 13–22 % low across codes 1–8.
- 2026-11-15 — Supply scaling inside a macro uses VDD² (same rule as B-11) — it reproduces Sinangil Fig. 13(b) within 7 % over 0.65–1.0 V and Jia's 0.85 V column energies within 5.5 %. It does not reproduce Sinangil's Table I values at 1.0 V (−11 … −35 %), which contradict Fig. 13(b) of the same paper; those points are reported, not fitted.
- 2026-11-15 — GATE B1 passed with the three M2 exceptions documented  — M4 ≤ 13 %, M1 ≤ 5.5 %, M2 ≤ 7 % in its operating range and over VDD; code 0 is not an operating point of a dense-input LLM layer and the 1.0 V table values contradict the paper's own Fig. 13(b). The area half of the gate is untested (inputs or not published) and is stated as such.
- 2026-11-15 — Per-layer and per-token event counts are derived from the model shape instead of read from `events.json` — the Part A runs saved totals only; the derived totals equal the saved ones exactly for linear layers (nrow 128 and 64, both result models) and for attention on CIM, so no rerun is needed. `run_ppl.py` writes per-layer counts from now on.
- 2026-11-15 — The result system's analog arrays are the M1 macro (65 nm) moved to 22 nm, not M2 — M1 has the simulator's computation model (bit-serial inputs, bit-sliced weights, column ADC per input cycle); M2 computes a 4-b × 4-b MAC per cycle with a 4-b output and cannot represent the 8-b / 6-b-ADC operating point. Cost: the 22 nm numbers rest on a 65 nm anchor and the scaling rule (three macros agree within 1.53× after scaling).
- 2026-11-15 — DRAM default 3.97 pJ/bit (HBM2), the lowest cited value, with GDDR5 / DDR3 values as alternatives — no LPDDR5 energy per bit was found, and with the lowest value the result "decode is dominated by weight streaming" is a lower bound on that share.
- 2026-11-16 — B5 uses AccelForge's `jia_jssc_2020` model instead of the CiMLoop Docker image — the CiMLoop repository is archived and points to AccelForge / HWComponents (same group) as the maintained versions of its macro models; AccelForge carries the same Jia and Sinangil macros and a notebook that reproduces Jia Table I, the data M1 is fitted to. Docker has no daemon in the cloud VM, and running AccelForge's example code in the cloud VM was refused by its safety check, so the run is on the local machine in a separate environment (`third_party/afenv`, git-ignored).
